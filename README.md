# browser-use MCP server v3.0

MCP-сервер для управления браузером на базе [browser-use](https://github.com/browser-use/browser-use) для развёртывания на сервере. Им пользуются внешние агенты со своей моделью: сервер даёт низкоуровневые инструменты (открыть, кликнуть, напечатать, прочитать), LLM на сервере не нужна.

**Один браузер, один агент одновременно.**

```
browser-mcp  (один процесс, порт 8000)
├── /mcp/browser   инструменты браузера → BrowserSlot (один Chromium, один владелец)
└── /health        жив ли сервер и кто держит браузер
```

## Как браузер переходит от агента к агенту

1. Первый агент, вызвавший любой инструмент, получает новый браузер с пустым профилем. Все его вызовы идут в этот браузер.
2. Пока никто другой не обращается к серверу, браузер остаётся у этого агента сколько угодно, даже если агент долго молчит.
3. Если обращается другой агент, его вызов ждёт до `BROWSER_BUSY_WAIT_SECONDS` (20 с):
   - текущий агент бездействует уже `BROWSER_HANDOVER_IDLE_SECONDS` (30 с) — его браузер закрывается, профиль, куки и загрузки удаляются, новый агент получает свежий браузер;
   - текущий агент работает — новый получает ошибку «браузер занят другим агентом, повторите через N с».
4. Если текущий агент держит браузер дольше `BROWSER_SESSION_MAX_SECONDS` (30 мин), ожидающий агент забирает браузер, даже если текущий активен: сразу после окончания его текущего вызова. Если никто не ждёт, лимит ничего не закрывает.
5. Браузер освобождается сразу, если агент вызвал `browser_close` или корректно завершил MCP-сессию (DELETE).

Агент, у которого забрали браузер, узнаёт об этом. Пока браузер у другого, он получает ошибку «ваш браузер был закрыт: …». Когда он снова получит браузер, первый ответ начнётся с `NOTE: your previous browser was closed …`, чтобы модель не продолжала работу со старой страницей. Ожидающие агенты обслуживаются по очереди.

### Как сервер различает агентов

| Клиент | Чем различается | Работает ли передача |
|---|---|---|
| Свой токен у каждого агента (`AUTH_TOKENS`) | Имя токена. Переподключение агента сохраняет его браузер | Да, на любом протоколе MCP |
| Протокол MCP 2025 (с handshake), общий токен или без него | `Mcp-Session-Id`: одно соединение = один агент | Да |
| Новый stateless-протокол MCP или stdio, общий токен или без него | Никак | Нет: все такие клиенты считаются одним агентом и делят браузер |

Если агенты подключаются по новому протоколу MCP, выдайте каждому свой токен в `AUTH_TOKENS`.

## Быстрый старт

### Docker (сервер)

```bash
cp .env.example .env          # задай AUTH_TOKEN или AUTH_TOKENS
docker compose up -d --build
curl http://localhost:8000/health
```

Порт публикуется только на `127.0.0.1`. Для доступа с других машин поставь перед сервером reverse proxy с TLS. Ответы стримятся (SSE), поэтому выключи буферизацию: `proxy_buffering off` в nginx. Таймаут чтения должен быть больше `BROWSER_BUSY_WAIT_SECONDS` плюс время самого действия, 120 с хватит.

### Без Docker

Локально нужен Chrome или Chromium. Если browser-use не найдёт его сам, укажи `BROWSER_EXECUTABLE_PATH`.

```bash
uv sync
uv run browser-mcp            # http://127.0.0.1:8000/mcp/browser
```

`BROWSER_PROXY=http://http.docker.internal:3128` работает только внутри Docker. Без Docker с ним не откроется ни одна страница. Чтобы видеть окно браузера, задай `BROWSER_HEADLESS=false`.

## Подключение клиента

- URL: `http://<host>:8000/mcp/browser`, транспорт Streamable HTTP.
- Заголовок: `Authorization: Bearer <token>`.
- JSON-конфиг: `{"mcpServers": {"browser": {"url": "https://browser.example.com/mcp/browser", "headers": {"Authorization": "Bearer <token>"}}}}`.
- Клиенты, которые умеют только stdio: `TRANSPORT=stdio uv run browser-mcp`. У stdio-сервера один клиент, передачи между агентами там нет.

## Инструменты

Каждое действие сразу возвращает новое состояние страницы: URL, заголовок, вкладки и содержимое, где интерактивные элементы помечены `[index]`. Отдельный вызов «посмотреть» между действиями не нужен.

| Инструмент | Что делает |
|---|---|
| `browser_navigate(url, new_tab?)` | Открыть URL |
| `browser_click(index \| x,y)` | Клик по `[index]` или по координатам со скриншота |
| `browser_type(index, text, clear?, submit?)` | Ввод текста; `submit=true` нажимает Enter |
| `browser_press_keys(keys)` | Клавиша или сочетание: `Enter`, `Escape`, `Control+a` |
| `browser_select_option(index, option)` | Выбрать пункт в выпадающем списке |
| `browser_scroll(direction?, pages?, index?)` | Прокрутка страницы или элемента |
| `browser_back()` | Назад |
| `browser_tab(tab_id, close?)` | Переключить или закрыть вкладку |
| `browser_wait(seconds?)` | Подождать загрузки и вернуть состояние |
| `browser_snapshot(screenshot?)` | Состояние без действия; скриншот с рамками `[index]` |
| `browser_screenshot(full_page?)` | Скриншот (JPEG) |
| `browser_read(start?)` | Страница целиком в markdown, длинные — частями |
| `browser_find(pattern, regex?)` | Поиск текста на странице, как Ctrl+F |
| `browser_close()` | Закончить работу: закрыть браузер, удалить профиль и освободить сервер для следующего агента |

Результаты отдаются только текстом, без дублирующего structured content: это экономит контекст клиента. Размер состояния ограничен `BROWSER_STATE_MAX_CHARS`, всё длинное читается через `browser_read`.

## Настройки

Все настройки с комментариями собраны в [`.env.example`](.env.example). Главные:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `AUTH_TOKEN` | — | Один токен для всех (не меньше 16 символов) |
| `AUTH_TOKENS` | — | Токены агентов: `pix-1:токен1,pix-2:токен2` |
| `BROWSER_HANDOVER_IDLE_SECONDS` | `30` | Сколько текущий агент должен бездействовать, чтобы ожидающий забрал браузер |
| `BROWSER_BUSY_WAIT_SECONDS` | `20` | Сколько вызов другого агента ждёт браузер до ошибки «занято» |
| `BROWSER_SESSION_MAX_SECONDS` | `1800` | После этого ожидающий агент забирает браузер даже у активного; `0` — без лимита |
| `BROWSER_WINDOW_SIZE` | `1280x900` | Viewport; иначе он равен экрану хоста и скриншоты огромные |
| `BROWSER_ALLOWED_DOMAINS` | — | Куда браузеру можно ходить |

`GET /health` показывает состояние браузера: `free`, `idle` или `working`, владельца (имя токена или начало id MCP-сессии), время простоя и число ожидающих.

## Тесты

```bash
uv run pytest
docker build --target test -t browser-use-mcp:test . && docker run --rm browser-use-mcp:test
```

Тесты не требуют браузера: он подменяется фейком. Проверяются передача браузера между агентами (простой, лимит длительности, очередь, `browser_close`, отключение), различение агентов по `Mcp-Session-Id` и токенам, инструменты и HTTP-приложение. Тесты не читают `.env`.

Версии всех зависимостей зафиксированы в `uv.lock`, Dockerfile использует его с `--frozen`. После правки зависимостей в `pyproject.toml` выполни `uv lock` и закоммить обновлённый `uv.lock`.

## Безопасность

- Без `AUTH_TOKEN`/`AUTH_TOKENS` любой, кто достучится до порта, управляет браузером. Порт публикуется только на `127.0.0.1`.
- `BROWSER_ALLOWED_DOMAINS` задаёт, куда браузер может ходить, включая переходы по кликам.
- `BROWSER_BLOCK_IP_ADDRESSES=true` запрещает только URL с IP-адресом. Имена вроде `localhost` или имена внутренних сервисов он не блокирует. Чтобы браузер не ходил во внутреннюю сеть, закрой контейнеру доступ к ней на уровне сети.
- Выполнения произвольного JavaScript нет.
- Каждый агент получает новый временный профиль браузера, который удаляется после закрытия.
- Контейнер работает под non-root пользователем, с `cap_drop: ALL`, `no-new-privileges` и лимитами CPU и памяти. Chromium в контейнере работает без своей песочницы (`--no-sandbox`), поэтому образ стоит регулярно пересобирать, чтобы получать обновления Chromium.
- При `LOG_LEVEL=DEBUG` browser-use пишет в лог текст, введённый через `browser_type`, включая пароли. На сервере держи уровень `INFO` или выше.

## Диагностика

- **«The browser is in use by another agent».** Браузер у другого агента, и тот был активен меньше `BROWSER_HANDOVER_IDLE_SECONDS` назад. Повтори через указанное время.
- **Агент получает «your previous browser was closed».** Он молчал дольше `BROWSER_HANDOVER_IDLE_SECONDS`, пока его ждал другой агент. Если модель агента думает медленно, увеличь этот параметр.
- **Агенты на новом протоколе MCP работают в одном браузере.** Сервер их не различает. Выдай каждому свой токен в `AUTH_TOKENS`.
- **Подробные логи:** `LOG_LEVEL=DEBUG`.

## Структура

```
src/browser_mcp/
  __main__.py        точка входа: HTTP (uvicorn) или stdio
  app.py             ASGI-приложение, /health, освобождение браузера при DELETE
  config.py          все настройки (env / .env)
  browser_server.py  /mcp/browser: инструменты и определение агента
  sessions.py        BrowserSlot: один браузер, ожидание, передача, лимиты
  driver.py          драйвер браузера на browser-use (BrowserSession + Tools)
  auth.py            bearer-токены, общий и на каждого агента
  logging_setup.py   единые логи (text/json)
tests/               pytest
```

Агентный эндпоинт `/mcp/agent` (задачи для агента browser-use с Ollama) убран в v3.0. Последняя версия с ним — коммит `e04e15b`.

## Ограничения

- Состояние хранится в памяти. После рестарта браузер и очередь пропадают, работает один инстанс.
- Драйвер использует внутренний API browser-use (`BrowserSession`, `Tools`), который меняется часто. При обновлении browser-use прогоняй живую проверку, а не только тесты.
- Куки между сессиями не сохраняются: каждый агент начинает с пустого профиля.
